# 国际化：语言切换（zh-CN / en）

> 所有者 2026-10-27 拍板：底座用 **i18next + react-i18next**；错误文案 **前端按 code 映射、未命中回落原 msg**；
> 迁移 **一次全量**；默认语言 **跟随系统**（`zh*` → 中文，其余英文），首启判定后立即落库。
> 本轮只做这两种语言。

---

## 0. 范围

| 翻 | 不翻 |
| --- | --- |
| 应用自己的界面文案：标题栏、侧栏、会话列表、输入区、空态、设置页、对话框、按钮、aria-label / title / placeholder | ACP agent 的输出与思考、用户输入、消息内容、文件内容 |
| 客户端产出的错误条文案（按 code 查表） | Rust 的 `tracing` 日志、设置读取的诊断 notes（见 §4.2） |
| 时间/日期的语言（`Intl` 随手走） | 代码块的语法高亮、代码主题名（`sincearc` / `one-dark` 是标识） |
| —— | 品牌与专有名词：SinceArc、ACP、MCP、SSH、WSL、JSON 等 |

新增第三种语言 = 加一份资源文件 + 枚举加一项，**不改任何调用点**；本轮不做。

---

## 1. 底座与资源布局

- `i18next` + `react-i18next`（版本锁在 `package.json`，不引 `i18next-browser-languagedetector`、
  不引 HTTP backend —— 资源随包，离线可用，语言判定我们自己写，见 §2.1）。
- 资源：`src/i18n/zh-CN.ts`（**唯一事实源**）、`src/i18n/en.ts`，**扁平点分 key**
  （`settings.appearance.language.label`），i18next 侧 `keySeparator: false` 按字面量查。
  用 TS 模块而不是 JSON：`keyof typeof zhCN` 直接就是全量 key 的联合类型，`t()` 拼错 key 是编译错误，
  `en.ts` 声明成 `Record<MessageKey, string>` 后少一条也编译不过 —— JSON 做不到这两点，得靠额外脚本。
- 初始化集中在 `src/i18n/index.ts`：`createInstance` + `initReactI18next`，
  `lng` 取已落库的语言，`fallbackLng: "en"`，`escapeValue: false`（React 已转义），`returnNull: false`。
- 缺 key 的两级兜底（按序）：`fallbackLng` 英文 → 仍缺则**原样显示 key**，同时 `console.warn`。
  不显示空白、不显示"未知文案"（否则漏译在界面上看不出来）。
- 复数：只在真的要区分单复数处用 i18next 的 `_one` / `_other`（英文用两份，中文只有 `_other`）；
  其余一律用具名插值 `{{name}}`，**不拼字符串**。
- 时间：现有 `src/lib/format.ts` 里写死的 `toLocaleTimeString("zh-CN")` 一并改成跟随当前语言；
  新增格式化一律走 `Intl.*`，不自己造月/日表。

## 2. 语言状态：唯一来源是 `settings.language`

- 落库：SQLite `settings` 表，key = `language`，值只允许 `zh-CN` / `en`。
  `AppSettingsDto` 加字段 `language`（默认 `en`，与 Rust 侧 `Default` 一致）。
- **不得**用 `localStorage` 存语言：设置的唯一来源是库，两处真相一定会打架。

### 2.1 首次启动的判定

1. 库里没有 `language` 这个 key → 读系统语言（`navigator.language`），按 §2.2 归一化；
2. 判定结果**立即写库**（与其它设置一样走 `settings_save`），之后不再重复判定；
3. 库里已有值 → 只做归一化校验，值不认识按 §2.2 兜底并记一条诊断。

### 2.2 归一化（同一判据只在这里写）

| 输入 | 结果 |
| --- | --- |
| `zh` 开头（`zh`、`zh-CN`、`zh-TW`、`zh-Hans`…） | `zh-CN` |
| `en` 开头（`en`、`en-US`、`en-GB`…） | `en` |
| 其余一切（空串、`null`、`fr-FR`、乱码） | **`en`**（默认动作，不报错、不空界面） |

`zh-TW` 也归到 `zh-CN`：本轮只有一份中文，不做繁体。这条是有意的取舍，写在这里避免以后被当成 bug。

### 2.3 切换即时生效

设置页改语言 → `settings_save` → `i18n.changeLanguage(next)` → `document.documentElement.lang = next`。
**不要求重启**，不做"重启后生效"的提示。切换失败（写库报错）→ 保留原语言，错误条按 §4 显示。

## 3. 设置页入口

「外观」分区新增一行内设置项（左 label 右控件，遵循 `docs/desktop-ux.md` §7.1 的行内设置项规范）：
**语言 / Language** —— 两档：中文 / English。选项标签本身**用当前语言显示**（切到英文后这一行仍是可读的英文）。

## 4. Rust 侧文案

### 4.1 错误：按 code 翻译，未命中回落

- `CmdError { code: u32, msg: String }` 结构不动，Rust 继续产出中文 `msg`（后端不引入语言维度）。
- 前端 `src/i18n/errors.ts` 维护 `code → key` 映射；渲染错误条时：
  - 命中 → `t(key, params)`；
  - **未命中 → 直接显示原始 `msg`**（兜底条款：新 code 漏映射不阻断功能、不吞错、不显示"未知错误"）。
- 映射表覆盖不到不是 bug，但每次 PR 顺手补；`errors.<code>` 的 key 与映射表一一对应，由门禁校验。

### 4.2 已知缺口（本轮不翻，记录在案）

设置读取时 Rust 造的中文诊断 notes（进诊断事件流）**保持中文**。理由：它们是"日志性质的人话"，
翻译它们等于把日志也搬进资源文件，收益低、维护面大。英文用户会在诊断流里看到中文，这是已知缺口。

**存进状态的文案不会跟着切语言**：例如标签页标题是在 `openTab` 时用当时的语言写进状态的，
切到英文后已打开的那个标签仍显示旧语言。彻底修法是状态里存 key、渲染时 `t(key)`，
本轮不做（要动 `useTabs` 的状态形状）；新开的标签一定是当前语言。

## 5. 代码层硬约定

1. **组件里不许出现中文字面量**（`src/**/*.tsx`、`src/**/*.ts` 中面向界面的模块）：一律 `t(key)`。
   门禁脚本查，白名单只有：注释、`*.test.ts`、`src/i18n/*.json`、日志/调试字符串（明确标 `// i18n-ignore`）。
2. key 用**语义名**，不用中文、不用英文原文：`chat.empty.title`、`settings.chat.contextMessages.label`。
3. `aria-label` / `title` / `placeholder` 与可见文案同一套 key，不留硬编码。
4. 插值用具名占位符；占位符集合两种语言必须相等（门禁校验）。
5. 迁移时**不顺手改文案内容**：先原样搬进资源文件，措辞调整另外做 —— 否则评审分不清"迁移"和"改文案"。

## 7. 明确不做

| 项 | 理由 |
| --- | --- |
| 第三种语言 / 繁体 | 加语言是"加资源 + 枚举"，需要时再说 |
| Rust 侧文案资源化（日志、诊断 notes） | 双份维护，收益低；欠账记在 §4.2 |
| agent 输出、消息、文件内容的翻译 | 那是用户数据 |
| RTL / 双向布局 | 中文与英文都是 LTR，没有验证对象 |
| 货币、时区、数字分组的本地化细节 | 本轮只做"时间跟着语言走" |
