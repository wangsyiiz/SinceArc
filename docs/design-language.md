# SinceArc 设计语言 v2

本文件是 UI 的**可执行约定**。改样式之前先读；与 `src/styles.css` 冲突时以本文件为准，
并同步改实现（文档先行，代码跟上）。

v2 的目标不是换风格，而是**把已有风格收敛成可检查的规则**：任意一个视觉值都能查到该用哪个令牌，
任意一条禁令都有工具在拦，而不是靠记忆和眼力。

沿用 v1 的取舍（石板蓝面阶、单色强调、暗色靠高光/浅色靠边框、所有状态变化都要补间），
v1 的十条硬教训全部保留（见 §8 §9 §10 §11 §12），并补上令牌表、状态矩阵、禁令与检查手段。

## 1. 令牌（唯一来源：`src/styles.css` 的 `:root`）

命名规则：`--s*` 面阶、`--l*` 线、`--i*` 字、`--a*` 强调、语义色直呼其名。**令牌之外没有颜色。**

> **落地状态（避免「引用了不存在的变量」这个老坑）**
>
> - **今天就在 `styles.css` 里**：`--s0..s3`、`--l1/l2`、`--i1..i3`、`--a1/ai`、`--d1/ok/warn`、
>   `--glass-1/2/control`、`--glass-blur/saturate`、`--radius-sm/radius/radius-lg/radius-card`、
>   `--row-active`、`--switch-*`、`--edge-highlight/hairline`、`--glass-border`；
> - **v2 新增、P1 才落地**：`--dur-fast/base/slow/slide`、`--ease-out/pop/slide`、五档 `z-index`、
>   字号令牌（`caption/small/ui/body/lead/title`）、间距档位说明。
>   在它们写进 `styles.css` 之前，代码里**不许**引用 —— `var(--x)` 未定义会让整条声明被丢弃，
>   v1 就因此让分段控件一直是直角。


### 1.1 面阶（层级用面阶差表达，不用阴影堆）

| 令牌 | Tailwind | 暗色 | 浅色 | 唯一用途 | 禁止 |
| --- | --- | --- | --- | --- | --- |
| `--s0` | `surface-0` | `#292d3e` | `#eeeeee` | 窗口底、代码块底 | 卡片、按钮底 |
| `--s1` | `surface-1` | `#2f3347` | `#fafafa` | 分栏面（侧栏/顶栏/内容卡） | 主按钮底 |
| `--s2` | `surface-2` | `#33384c` | `#ffffff` | 卡片、浮层实心面 | 整页底 |
| `--s3` | `surface-3` | `#3c425a` | `#ededed` | 悬停/激活面、行内代码底 | 大面积铺底 |
| `--row-active` | — | `s3` | `#e6e6e6` | **列表选中面只用它** | 用 `s3` 代替（浅色下看不出） |

**方向警告**：暗色是「数字越大越亮」，浅色是「数字越大越暗」。任何新增用法都要在两档里各看一眼。

**白色的唯一用途是「光」**：上缘 1px 内高光、hover 扫光。`bg-white/[0.0x]` 一律换成面阶色 ——
白色叠在石板蓝上会发灰发雾。

### 1.2 线

| 令牌 | Tailwind | 用途 |
| --- | --- | --- |
| `--l1` | `line-1` | 分隔线、常规边框、`sc-pane` 边 |
| `--l2` | `line-2` | 强描边：输入框常态、hover 边框、聚焦前状态 |

边框宽度只有 **1px**。要更重的边界请提高面阶或改描边颜色，不要 2px。

### 1.3 字

| 令牌 | Tailwind | 暗色 | 浅色 | 用途 |
| --- | --- | --- | --- | --- |
| `--i1` | `ink-1` | `#f6f6f6` | `#060606` | 正文、标题 |
| `--i2` | `ink-2` | `#c0c0c0` | `#4a4a4a` | 次要说明、标签 |
| `--i3` | `ink-3` | `#b2b2b2` | `#6e6e6e` | 占位符、弱提示、未选中分段项 |

字色只有这三档。**不要用 opacity 调弱文字**（叠加后对比度不可预测，浅色下会直接掉到不可读）。

### 1.4 强调与语义

| 令牌 | Tailwind | 用途 | 禁止 |
| --- | --- | --- | --- |
| `--a1` | `accent-1` | 主按钮底、链接、光标、选中描边 | 大面积铺底、正文色 |
| `--ai` | `accent-ink` | 主按钮上的字 | 用在非强调底上 |
| `--d1` | `danger-1` | 破坏性按钮文字、错误边框、必填星号 | 当装饰色 |
| `--ok` | `ok-1` | 成功态 | 当强调色 |
| `--warn` | `warn-1` | 需注意但未失败 | 当错误色 |

强调色是**单色**：浅灰底 + 近黑字（暗色）、深灰底 + 白字（浅色）。不引入彩色 accent。

### 1.5 间距（4px 基准，只允许这些档）

`2 / 4 / 6 / 8 / 10 / 12 / 16 / 20 / 24 / 32 / 40`

对应 Tailwind：`0.5 1 1.5 2 2.5 3 4 5 6 8 10`。

**禁止任意值**：`w-[437px]`、`gap-[7px]`、`mt-[13px]`。需要新档位先在这里加一行，再改代码。
（真发生过：弹层位置用常数 −179px 估算，一改文案就飘。）

### 1.6 字号与行高

| 档 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `caption` | 11 / 16 | 徽标、时间、极小标注 |
| `small` | 12 / 18 | 分段控件、表头、次要行 |
| `ui` | 13 / 20 | 按钮、表单标签、列表标题 |
| `body` | 14 / 22 | 正文基准（`body` 字号） |
| `lead` | 16 / 24 | 区块标题 |
| `title` | 20 / 28 | 对话框标题、空态主标题 |

正文字号不变：**14px**。改它等于改所有屏幕的排布，属于单独提案。

### 1.7 圆角

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--radius-sm` | 6px | 行内代码、小徽标、标签 |
| `--radius` | 8px | 按钮、输入框、分段控件（轨道与滑块同值） |
| `--radius-lg` | 12px | 卡片、浮层、对话框、`sc-pane` |

滑块这类小元素的圆角与轨道**同值**，不按同心公式算小 —— 22–26px 高的元素上 4px 形同直角。
对话框一律 12px（v1 里有 14px 的散值，v2 归一）。

### 1.8 光与边（主题令牌，不逐组件判断）

| 主题 | `--glass-border` | 高光 |
| --- | --- | --- |
| 暗色 | `transparent` | `--edge-highlight`（上亮下暗两道 inset） |
| 浅色 | `var(--l1)` | `none` |

暗色靠内高光划界，浅色靠 1px 边框 + 面阶差。**不要给浮层加外投影**：投影在深色底上是一片脏雾，
层次交给高光与面阶。

### 1.9 动效

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--dur-fast` | 110ms | 出现、按下反馈 |
| `--dur-base` | 160ms | 默认（颜色、边框、阴影、透明度、位移） |
| `--dur-slow` | 200ms | 分栏展开 / 收起 |
| `--dur-slide` | 420ms | 分段滑块横移、滚动条淡回 |
| `--ease-out` | `ease-out` | 默认 |
| `--ease-pop` | `cubic-bezier(0.2, 0.9, 0.3, 1)` | 对话框、菜单出现 |
| `--ease-slide` | `cubic-bezier(0.22, 1, 0.36, 1)` | 滑块横移 |

**不对称时长是有意的**：出现要跟手（110ms），消失可以慢（420ms）。两边对称会显得拖沓。

**禁止 `transition: all`**：它会过渡不相关属性，GPU 合成不可控；按属性列举。

### 1.10 层叠

只有五个层级，多了说明结构没想清楚。

| 层 | z-index | 内容 |
| --- | --- | --- |
| 内容 | 0 | 消息、列表、轨迹 |
| 吸附 | 10 | 顶栏、底部输入浮层 |
| 浮层 | 20 | 下拉、菜单、气泡 |
| 模态 | 30 | 对话框、抽屉 |
| 提示 | 40 | 全局提示条 |

### 1.11 焦点

键盘焦点**必须可见**，且两档主题下都看得见：`outline: 2px solid var(--a1); outline-offset: 2px`。
不许 `outline: none` 了事；确实要去掉的，必须同时在原位给等价的可见样式（例如输入框换 `--l2` 描边）。

## 2. 材质三层

| 类 | 用途 | 实现要点 |
| --- | --- | --- |
| `.sc-pane` | 分栏（侧栏 / 轨迹 / 主区） | 透明底 + 1px 边框 + 12 圆角；底色由窗口统一提供 |
| `.sc-glass` | 浮层（输入框、权限条、抽屉、对话框） | `--glass-1` 半透明 + `blur(16px) saturate(1.6)` |
| `.sc-control` | 控件（按钮、行 hover） | 只给上缘内高光，**底色由调用方给** |

三者都在 `@layer components` 里。**unlayered 的组件类会压过所有 Tailwind 工具类** ——
v1 就栽在这：`.sc-control` 自带 `background`，调用方的 `hover:bg-*` 永远无效。

## 3. 组件状态矩阵

每个基础件 × 每档状态都要有明确表现。表里写的是**必须**存在的差异，不是全部细节。

### 3.1 按钮

| 状态 | 主按钮（`accent-1` 底） | 次按钮（`surface-1/2` 底 + `line-1` 边） | 幽灵按钮（无底无边） |
| --- | --- | --- | --- |
| default | `a1` 底 / `ai` 字 | `s2` 底 / `l1` 边 / `i1` 字 | `i2` 字 |
| hover | 亮度 +8%（不改字色） | 底变 `s3`、边变 `l2` | 字变 `i1`、底 `s3` |
| active | 亮度 −4% | 底 `s2`、无额外高光 | 底 `s3` 加深一档 |
| focus-visible | 焦点环（§1.11），offset 2px | 同左 | 同左 |
| disabled | 不换色，改 `opacity` **0.45 + `cursor: not-allowed`** | 同左 | 同左 |
| loading | 保留宽度与底，文字换成加载态；**不许宽度跳动** | 同左 | 同左 |

规则：

- 禁用**必须同时给原因**（`title` 或旁边一行 `ink-3` 文案），只变灰等于让用户猜；
- 危险操作用 `danger-1` **字色**，不是红底实心（红底在深色主题上会跳出来抢注意力）；
- 一次操作只有一个主按钮。

### 3.2 输入框 / 文本域

| 状态 | 表现 |
| --- | --- |
| default | `s1` 底、`l2` 描边、`i1` 字、`i3` 占位符 |
| hover | 描边 `l2` 保持，底色 `s2` |
| focus | 描边 `a1`（**不用发光/阴影**），光标可见 |
| invalid | 描边 `d1` + 下方 `ink-3` 一行原因 |
| disabled | `opacity 0.5`、`cursor: not-allowed`，值仍可读 |
| readonly | 底 `s1`、无描边、字 `i2`（与 disabled 区分：能选中复制） |

**必填**：标签后跟红色 `*`（`text-danger-1`、`aria-hidden`、`title="必填"`），input 加 `aria-required`。
**可空**：标签里写「（可空）」，不要用星号的反面表达。
**保存被禁用时旁边必须写清还缺什么**，且一次说全（`还缺：名字、@ 短名`）。

### 3.3 下拉 / 分段控件

**不用原生 `<select>`**（样式不可控、深浅主题下表现不一致、键盘行为与我们自绘菜单不同）。
两档以内用分段控件，三档以上用自绘菜单。

| 状态 | 分段控件 | 自绘菜单 |
| --- | --- | --- |
| default | 轨道 `switch-track`、未选中项 `i3` | 触发器同次按钮 |
| hover | 未选中项字色 → `i2` | 菜单项底 `s3` |
| selected | 滑块 `switch-thumb`、字色 `i1` | 勾 + 字色 `i1` |
| open | —— | 浮层 `sc-glass` + `ease-pop` 150ms |
| disabled | 轨道 `opacity 0.5`、项 `i3` 且不可点 | 菜单项 `opacity 0.45` |

**「继承/跟随」类选项三条铁律**（v1 §9，仍然有效）：

1. 全场只允许一个勾：选中「跟随」时，下面的具体值**不许**再打勾；
2. 继承项必须在行尾显示它当前继承到的**实际值**（用户要知道「跟随之后生效什么」）；
3. 别自造术语：这一档就叫「跟随 Agent」（连接级）/「跟随连接默认」（会话级），
   不写「不指定」「随 agent 默认」「未设置」。

### 3.3a 组合框（可输入 + 下拉补全）

路径、命令、名字这类「可以自由输入、但有收敛集合」的字段，用组合框，不用纯下拉也不用裸输入。
参照 VSCode 地址栏的形态：**输入框本身可编辑，下拉只是补全，不是唯一入口**。

| 状态 | 表现 |
| --- | --- |
| default | 同 §3.2 输入框；右侧一个细小的展开箭头（`ink-3`，hover 变 `ink-2`） |
| 输入中 | 输入后 **250ms 防抖**再请求；请求在飞时用递增序号丢弃过期结果（只认最后一次） |
| 有建议 | 浮层从下方展开（空间不足向上翻，位置实测），只列**目录**，每项：目录名 + 完整路径（`ink-3` 小字） |
| 键盘 | `↑/↓` 移动、`Enter` 选中、`Tab` 选中并跳到下个字段、`Esc` 关闭且**不改**输入值 |
| 收起 | 点击外部、`Esc`、失焦；重开时输入未变则沿用上次列表 |
| 空输入 | 给「常用位置」：最近用过的 5 个 + 家目录 |
| 值非法 | 输入框保持原样（不静默纠正），旁边 `danger-1` 一行说明，保存禁用并写清原因 |

三条硬规则：

1. **前端不做路径归一**：`~` 展开、大小写、分隔符、家目录、是否存在 —— 全部后端回答（同 E6 原则）；
2. **建议不等于限制**：用户输入一个列表里没有的路径也必须能保存（只要后端确认存在）；
3. **不许静默纠正**：纠错靠一行说明，不靠改用户输入 —— 用户看到的必须还是他打进去的东西。

### 3.4 浮层（下拉 / 菜单 / 气泡）

- 材质 `sc-glass`，圆角 `--radius`（菜单）或 `--radius-lg`（面板），边界按 §1.8；
- **位置必须实测**：用触发元素与面板的 `getBoundingClientRect()` 计算，空间不足时翻转；
  **禁止常数估算**（v1 真发生过：写死 −179px，改文案就飘）；
- 点击外部关闭、`Esc` 关闭、打开后焦点进入面板、关闭后焦点回到触发器；
- 出现用 `ease-pop` 150ms，消失直接移除（不做退场动画，避免关闭时残影）。

### 3.5 对话框

- `dialog.sc-dialog`：玻璃 + 12px 圆角 + 1px `l1` 边，`::backdrop` `rgb(18 20 30 / 0.55)` + `blur(4px)`；
- 标题 `title` 档，正文 `body`，按钮区右对齐，主按钮在最右；
- **破坏性操作**（删除、断开、清空）必须写清后果与范围，一次确认，不做二次确认链；
- `Esc` = 取消，不 = 确认。

### 3.6 列表行 / 会话项

| 状态 | 表现 |
| --- | --- |
| default | 透明底，标题 `i1`，副标题 `i3` |
| hover | 底 `s3` |
| active（当前项） | 底 `row-active`，标题 `i1`，副标题 `i2` |
| focus-visible | 焦点环 |
| 未读/进行中 | 左侧 2px `a1` 竖条（**不用红点**，红点在深色底上像报错） |

**选中不许改 `font-weight`**：字宽变化会触发重排，抖一下比颜色跳更刺眼。

### 3.7 徽标 / 状态点

| 语义 | 表现 |
| --- | --- |
| 已连接 | `ok` 点 + `i2` 字 |
| 连接中 | `a1` 点，呼吸动画 1.6s |
| 断开 / 错误 | `d1` 点 + `d1` 字（仅错误本身用红，其余保持 `i2`） |
| 未测试 | `i3` 空心点 |

徽标高度 18px、圆角 `--radius-sm`、字号 `caption`。

### 3.8 空态 / 加载态 / 错误态

- **空态**：一句说明「这里会有什么」+ 一个主操作（可无）+ 可选一句为什么现在空
  （例：`这个会话还没有消息。@ 一个成员开始提问。`）；
- **加载态**：骨架屏优先于转圈；超过 300ms 才出现，避免闪；
- **错误态**：`d1` 标题 + `ink-3` 一行原因 + 明确的重试动作；错误文案必须写「哪一步失败了」，
  不写「操作失败」这种无信息量的话。

## 5. 禁令清单（每条都带真实事故）

| # | 禁止 | 事故 |
| --- | --- | --- |
| 1 | 颜色字面量（`#fff`、`rgb(...)`、`bg-white/10`） | 白色叠石板蓝发灰发雾；浅色主题直接失效 |
| 2 | 任意值（`w-[437px]`、`gap-[7px]`） | 弹层位置用常数 −179px 估算，改文案就飘 |
| 3 | 自绘浮层用常数定位 | 同上；必须 `getBoundingClientRect()` 实测 |
| 4 | 原生 `<select>` / `<input type=checkbox>` | SSH 认证的 select 与设计语言不符，审计抓出后改成两段式按钮组 |
| 5 | `transition: all` | 会给 SVG 节点加不该有的动画（轨迹图） |
| 6 | 写死浮层高度留白（`pb-32`） | 输入框变高时盖住最后一条消息；必须 `ResizeObserver` 实测 |
| 7 | 用 `opacity` 调弱文字 | 浅色主题下对比度掉到不可读 |
| 8 | 选中改 `font-weight` | 字宽变化触发重排，视觉抖 |
| 9 | 禁用只变灰、不给原因 | 用户不知道还缺什么 |
| 10 | 行内 `style` 覆盖令牌 | 主题切换时失效，且无法被检查工具发现 |
| 11 | `var(--x)` 未定义就使用 | 整条声明被判无效丢弃，不退回 0（分段控件曾一直是直角） |
| 12 | unlayered 组件类自带 `background` | 压过所有 `hover:bg-*`，hover 静默失效 |

## 6. 检查手段（P1 落地，写在测试里而不是口号里）

`src/lib/style-guard.test.ts`（照 `layering.test.ts` 的路子，零依赖 node:test）扫描 `src`：

1. `.tsx/.ts` 里出现 `#[0-9a-fA-F]{3,8}`、`rgb(`、`hsl(` → 红（白名单：`styles.css` 与 `types.gen/`）；
2. 出现任意值写法 `-[0-9]+px]` / `-[0-9.]+rem]` → 红；
3. 出现 `<select`、`type="checkbox"` → 红；
4. 出现 `transition: all` / `transition-all` → 红；
5. 出现 `outline-none` 且同一 class 串里没有 `focus-visible:` → 红。

每条都要求**实测故意违规会红**，否则这条测试就是装饰品。
检查工具拦不住的（视觉判断），走 §7 的人工核对。

## 7. 自检（改完 UI 至少核对一次）

- 产物里目标规则还在不在（`grep` 编译后的 CSS）；
- 暗色、浅色各看一遍 —— 同一令牌在两档里的明暗方向可能相反；
- 新加的交互元素有没有落到 `@layer base` 那条兜底过渡上；
- hover 时同时变化的几样东西（背景、文字、边框）是不是**同步**开始
  （颜色挂在子元素上时最容易漏：背景 160ms 渐变、文字同帧瞬跳，比都不渐变还难看）；
- 键盘走一遍：Tab 顺序、焦点可见、`Esc` 关闭。

## 8. 三个静默失败（CSS 不报错，必须看渲染）

1. **`var(--x)` 未定义** → 整条声明被判无效并丢弃，不退回 0；
2. **unlayered 组件类压过所有工具类** → 调用方的 `hover:bg-*` 永远无效；
3. **`scrollbar-width` / `scrollbar-color` 一旦不是 `auto`，Chromium 会整体忽略 `::-webkit-scrollbar` 自定义**。

## 9. 滚动条

- 宽 10px，无上下箭头（`::-webkit-scrollbar-button` 全部 `display: none`）；
- thumb 用 `border: 3px solid transparent` + `background-clip: padding-box` 收成 4px；
- 静止 `--l1` 28%，滚动中 85%，停止 600ms 后淡回（不对称：亮得快、淡得慢）；
- 伪元素不吃 `transition` 时，用逐帧改变量（`--sb-alpha`）实现。

## 10. 截断与保留必须写在界面上

- 凡我们**主动截断或清理**的数据（思考只留开头 8KB、轨迹保留 90 天、历史分页），
  必须在对应位置常驻一句说明，不等用户发现不一致再问；
- 措辞只讲事实与后果：「思考过程只保留开头 8KB」✓ ／「因存储优化截断」✗；
- 被截断的条目本身带可见标记（「…（已截断）」）。

## 11. 文案

- 中文，术语固定：会话 / 成员 / 轨迹 / 连接 / 提问 / 模式；
- 按钮用动词（「删除会话」不是「确定」）；
- 错误文案三段式：哪一步失败 + 看到的现象 + 下一步能做什么；
- 不用「请稍候」这类没有信息量的等待文案，说明**在等什么**。
