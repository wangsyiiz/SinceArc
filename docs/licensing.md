# 许可与商业模式

> 拍板：**客户端 Apache-2.0（永久），服务端闭源，贡献用 DCO**（2026-10-27，所有者）。
> 这份文档写清「什么免费、什么可能收费、哪三条线不能越」，避免以后被当成「假开源」。

## 1. 免费的部分（永久）

**客户端的一切功能，永久免费且开源。** 不连我们的服务也能用完整功能：连本地 / WSL 里的 agent、
会话与轨迹落库、多 agent 群聊、审批、代码高亮、长列表、导出等。

判断标准很简单：**功能在仓库里，就没有任何开关挡着它**。不登录、不填 key、不联网也能跑。

## 2. 可能收费的部分（服务端能力）

订阅卖的是**服务**，不是解锁客户端里的代码。预期范围（具体以发布时的说明为准）：

| 能力 | 为什么在服务端 |
| --- | --- |
| 账号与多设备同步 | 需要中心存储与冲突合并 |
| 托管 agent（不在你机器上跑） | 算力与额度在我们的机器上 |
| 团队协作（共享会话/轨迹） | 需要多租户与权限模型 |
| 用量与额度统计 | 需要服务端计量 |

## 3. 三条红线（自我约束，不是给别人看的）

1. **客户端不含付费锁**。仓库里不出现「功能已写好、但要 license 才亮」的分支。
   订阅能力做成服务端 API，客户端只是「带 token 调接口」。这条同时消掉了「fork 绕过」的问题——
   没有东西可绕。
2. **Pro 代码不进公开仓**。放在独立私库或独立服务，不在公开仓里用注释分隔。
3. **边界写在明面上**。README 与本文档必须同步更新；新增收费点要在这里先写清楚再实现。

## 4. 你可以拿它做什么

Apache-2.0 允许：商用、修改、闭源分发、放进你自己的产品。义务只有三条形式要求：

- 附上 `LICENSE` 副本；
- 保留 `NOTICE` 里的归属声明；
- 标注你修改过的文件。

**不能**做的事：把本项目的代码换个协议再授权给第三方（例如声称这是你的专有代码），
以及使用 `SinceArc` 名称与图标（见 `TRADEMARK.md`）。

## 5. 商标

`SinceArc` 名称与 logo 不随代码授权（Apache-2.0 §6 本来也不授予商标权）。
fork 可以做，但**必须改名换标**。这一条不是限制使用，是防止有人顶着同一个名字发版。

## 6. 贡献：DCO，不签 CLA

每个提交带 `Signed-off-by`（`git commit -s`），即声明「有权按 Apache-2.0 提交」。
**有意的后果**：社区贡献的代码永久受 Apache-2.0 约束，项目方不能把含社区贡献的部分整体改协议。
换来的是贡献门槛最低——不用注册、不用签任何额外文件。

当前仓库的提交全部来自所有者本人，所以「换协议」的自由在合入第一个外部 PR 之前仍然存在；
之后就不再有。这个取舍是有意的。
